# Frontend

## Across the screens

- **Routing** (`src/routes.ts`, `parseHash`/`hashFor`, unit-tested): the screen lives in the URL hash, so Back/Forward work without a router. `#today`, `#today/YYYY-MM-DD` (an earlier day; a future or unreal date is today), `#journal` (old `#readonly` links land here), `#analytics/<id>`, `#tracks`, `#tracks/<id>` (that track's sidebar open; an unknown or archived id opens the list). No hash or anything unknown is Today. Moving between days on Today, picking a track in Analytics, and switching from one open sidebar to another **replace** the history entry; opening a sidebar from the list pushes one, and closing it then goes back (`sidebarPushed` in `App.vue`).
- **Toolbar choices** (`src/preferences.ts`): "Show private tracks" (the eye, `PrivateToggle.vue`, on Today and the Journal; Analytics follows it), the Journal layout and Editable days are saved on the server (`/api/preferences`) with **one value for desktop and one for mobile**, chosen by `useIsMobile()` (under 1024px), switching live as the width crosses it. Starting values: Days down / Days down, private off / off, Editable days All / Today. Loaded once per page; a value changed before the load answers is kept, not overwritten by it; a failed save keeps the value for the page and toasts "Could not save the setting".
- **Following the day** (`src/useToday.ts`): Today, the Journal, Tracks and Analytics keep a reactive `today`, moved on one second after local midnight and checked on focus/visibility, with a quiet reload on a new day or when data is over 5 minutes old (the dashboard widget keeps its own copy of the same code).
- **Editable days** (`src/editableDays.ts`, Tickdroid's `EditableDays.isEditable`; the button and its menu are `EditableDaysMenu.vue`, MDI's `calendar-lock-outline`, `calendar-lock-open-outline` while set to All): a locked day shows read-only values instead of controls (the ✓ in the theme colour or nothing, a counter's number with a muted "0"), a click on them toasts, and its notes are read-only, with no way to add one. In the Journal a locked day looks exactly like an open one at rest (no lock, no dimming, as in Tickdroid) and keeps that look under the pointer, with focus and on a touchscreen. On both screens the toast reads "This day is locked. Use the Editable days button to change that."
- **Notes** (`NoteField.vue`, `NoteText.vue`): shown with line breaks kept, clamped to three lines with "Show more". Editing in place: Enter saves, Shift+Enter is a new line, Escape cancels, **losing focus saves**; saving it empty (Enter or clicking away) deletes the note. There is no ✕: it read as "close this field". The hint under the field says so. Saving sends `notes/set` (or `DELETE /api/notes` for empty), only when the trimmed text changed. Note text is always rendered escaped (`v-text`/`{{ }}`, never `v-html`).
- **Writes**: yes/no days are written with `POST /api/ticks/set` and the state the control now shows, counters with `POST /api/ticks/increment` and ±1, never `toggle` or an absolute value worked out from what the page loaded, so a click never undoes another client's change. No optimistic updates: the control shows the server's answer. On Today and in the Journal (`src/cellWrites.ts`) a cell's writes (its tick, or its note) go one at a time, in the order they were made, so its last answer is its value; a load that started before a cell's write leaves that cell as the write left it; and a load replaces only the days it asked for, a cell missing from its answer being removed (sparse), so a reload and a page of older days can arrive in either order.
- **Track types**: wherever code branches on `track.type`, an unknown type must take a read-only branch ("Not supported yet" on Today, the stored value in the Journal), never the counter branch. **Number and Choice**: a day without a tick is `null` in the value maps (`?? null`, never `?? 0`: a Number's 0 is a reading); Yes/No and Counter read null as 0. Both share `NumberField.vue` (a text field: Enter or losing focus saves, Escape restores, empty clears, text that isn't a number or a refused negative stays with a toast, "Enter a valid number") and `ChoiceField.vue` (`NcSelect`, clearable); an empty value shows "…" (U+2026) in both, and on the Journal's Choice button before its drop-down mounts, the field's hidden while it has focus. `NumberField` takes an optional `unit`, which Today passes under 1024px (`useIsMobile`) for a Number with a unit: the field and the unit then share one box (its root `<label>`, which draws the ring, so the focus ring goes round both and a tap on the unit focuses the input; without a unit the label is `display: contents` and the input draws the ring, as the Journal's always does). In the box the input never gets narrower than the value as shown (`--value-chars`, its length or 1 for the "…", times 1ch, plus its 12px of padding) and the unit, uncapped, is cut with "…" only when the box runs out of room; with focus the unit hides and the input has the whole box. `ChoiceField` shows vue-select's ✕ while its list is open too (`.picked` and a global `.vs--open .vs__clear` rule outranking its `v-show`), as the Journal opens the list the moment it mounts and would never show the ✕ otherwise; a press on the ✕ is kept from taking the focus (`keepFocusOnClear`: vue-select keeps it only for presses on the field and the ▾, and the search field losing focus closes the list, and the Journal's bar, before the click that clears), and after clearing an open list is closed (a tick later, as `clearSelection` refocuses the search field), as a pick closes it; with the list closed (Today) focus stays. Both rely on vue-select's class names: recheck after an `@nextcloud/vue` bump. On Today the field and the drop-down share the value column's 140px (see `.claude/rules/today.md`); in the Journal a Number's bar holds the field and the unit, a Choice's a plain button that mounts the `NcSelect` when used (one per grid at most), and the bar stays open while active (`.activeBar`); on a touchscreen both show text and a tap opens the field or list (see `.claude/rules/journal.md`). Days down's headers are at most 120px (96px), Tracks down's day columns fit the widest number on screen (`--day-number-width`, never shrinking, floor 56px/48px; the rule is `.grid.wideDays`, two classes, as the phone rule on `.grid` comes later and would otherwise hold every column at 34px), and a day cell has no `max-width`, so a long number or a touchscreen Counter's "− n +" widens its column rather than being cut or spilling into the next (a Choice's label is still cut at `--cell-label-width`); both draw a unit line under the names only when a track on screen has a unit. Only tracks on screen count, never hidden private ones. Analytics treats them as days with an entry, shading the heatmap with `trackLevel`. Details (`TrackSidebar.vue`) edits a Number's settings and renames a Choice's options in place; New track (`NewTrackDialog.vue`) posts JSON so `options` is a list.

## Shared front-end modules

Small, Vue-free TypeScript modules in `src/`, used across the screens and the dashboard widget (the pure ones unit-tested with Vitest, `src/*.test.ts`):
- `types.ts` — `Track` (with `TrackOption`), `Tick`, `Run`, `TrackStats` (one `GET /api/stats` entry), `Note`, `Preferences`, `JournalLayout` and `EditableDays`.
- `dates.ts` — `userLocale`, local `YYYY-MM-DD` helpers (`toDateStr`, `parseDateStr`, `addDays` via `setDate` so DST days stay one day, `todayStr`), `fmtDate` ("Mon 5 Oct 2026"), `fmtDayLabel` ("Mon 19 Oct", with the year outside this one), `dayHeading` (Today's title and the line under it), `squaresEnd` (the newest of Today's squares), `isWeekend` and `isoWeek` ("2026-W46", counted on UTC calendar days: dividing the time between two local midnights by 24 hours moved every later week one bucket up in years where January is summer time, Sydney's 2021 for one).
- `heatmap.ts` — heatmap shading: `LEVEL_ALPHA`, `levelFor`, `fillFor`, `valueText`, `getPrimaryColor`, `hexToRgba`, and for every type `trackLevel` (a Number between its stats' `minValue` and `maxValue`, an ordered Choice by place, both as `rangeLevel`: lowest level 1, highest 4, all equal 2; a plain list level 2), `trackValueText` ("10.4 km", a label, "No value"), `numberText` and `choiceLabel`. The levels live here so a change after Martin's look is one edit.
- `numberValue.ts` — the web's copy of `NumberValue`: thousandths (`toMilli`, `roundMilli`, half away from zero on integers, since `Math.round` rounds -2.5 to -2), `formatNumber` (rounded on thousandths before `Intl`, which would round the double), `parseNumber` (the locale's decimal separator, its group separator only between groups of three, a point as decimal where grouping isn't one, `-` or `−`; empty is null, anything else `'invalid'`), `toWire` and `sameAsStored`. Numbers follow `userLocale`, as dates do.
- `api.ts` — every read sends `includeAllTypes`; `setValue` (a Number's or Choice's day, `""` to clear), `renameOption`; `fetchTracks(includeArchived?)`, `fetchTicks(from, to, trackId?)` (one track's with a `trackId`, which only Analytics sends), `fetchStats(today, {trackId?, includeRuns?})`, `fetchNotes`, `setNote`, `deleteNote`, `setYesNo`, `incrementCounter`, `fetchPreferences`, `savePreference`, and `preferStrictHandling()`, which each entry point (`main.ts`, `dashboardApp.ts`) calls once before mounting: an axios interceptor that sends `Prefer: handling=strict` on requests to Tickbuddy's API only (WebDAV reads `Prefer`, so other URLs must not get it).
- `strictHandling.ts` — `PREFER_STRICT`, `isTickbuddyApiUrl`, and `httpStatus(e)` / `errorReason(e)` for reading a failed request defensively, like `ocsError.ts`. `errorReason` is null when the answer has no `reason` (Nextcloud's own errors).
- `cellWrites.ts` — `tickKey`, `cellWrites()` (a cell's writes one at a time, and which cells were written since a load started), `keepCells` and `replaceDays`; see "Writes" above.
- `routes.ts`, `preferences.ts`, `useToday.ts`, `editableDays.ts`, `runText.ts`, `journal.ts`, `trackMenu.ts` — see above, and the screen rules (`today.md`, `journal.md`, `tracks.md`). `icons.ts` holds the Material Design Icons paths, copied in rather than a dependency.
- `publicLinks.ts` — the Public links tab's and the Tracks page's words: `linkCountText`, `trackSubname`, `linkDetails`, `lastUsedText` ("Last used yesterday, 22:10"), `revokeText`, `archiveLinksText`, `exampleBase` (an address up to `/ping/`) and `exampleDates`.
- `writeErrors.ts` — the shared failure handling for writes. `writeFailed` (ticks and notes, on Today and in the Journal): a `423` with `reason: "archived"` shows "Exercise is archived, so the change wasn't saved." and reloads; a `404` with `reason: "trackNotFound"` reloads too (never a 404 without one: that is Nextcloud's while the app is disabled); any other answer with a `reason` shows the server's message, one without shows "Could not save the change" ("Could not save the note" for notes). `refusedAsReadOnly` (track changes on the Tracks page) reloads and toasts on any 423. Archiving a track already archived elsewhere (423 `archived`) counts as a successful archive.

## Labels

- **No "…" on labels**: no button or menu label ends in "…" (the Tracks page's ⋯ menu says "Import" and "Export"). An ellipsis only marks something in progress ("Exporting…") or a placeholder's example list.

## `@nextcloud/vue` workarounds in place

The reasons are in the nextcloud `vue-frontend` skill. Don't remove these:

- `npm run typecheck` after every `@nextcloud/vue` bump: the only check that sees
  component prop types. It does not catch CSS or layout regressions.
- The Journal's "Go to date" popover wraps `NcDateTimePickerNative` in a
  fixed-width `.datePicker` div (`JournalView.vue`).
- `NcSelect` is sized with `.myClass:global(.nc-select.v-select.select)` (`ChoiceField.vue`,
  the Decimal places selects); `ChoiceField.vue` also removes the list's 160px minimum
  with a global rule on `.nc-select__dropdown.vs__dropdown-menu`.
- `NumberField.vue` copies `NcInputField`'s box-shadow ring instead of core's input border.
- `NoteField.vue` grows `NcTextArea` from `scrollHeight`.
- Plain buttons (grid headers, Journal cells, "Show more") are styled under their
  component's root class, reset `background` on `:hover`/`:focus`, and take
  `margin: 0 !important`.
- `JournalCell.vue` zeroes core's checkbox label margin under `.cell .checkboxSlot`;
  core and library classes in `<style module>` are written `:global(...)`.
- `TracksView.vue` uses three classes (`.archivedItem .handleSpace.handleSpace`) to
  outrank a library component's scoped root rule.
- Icon buttons carry a native `title` matching their `aria-label` (v9 has no Tooltip directive).
- The navigation items are hash links, not router links, so `NcAppNavigationItem`
  doesn't close the drawer on a phone: `App.vue`'s `closeNavigationOnMobile` emits
  `toggle-navigation` `{ open: false }` on `@nextcloud/event-bus` (skipped on a
  click with a modifier key, as the library does).
